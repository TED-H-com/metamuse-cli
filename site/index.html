Turn comments into a recap with sources.

把留言與字幕，整理成有來源的回顧。

Have event feedback to review or a transcript to quote? Your AI assistant helps you make sense of it. MetaMuse keeps the originals, finds matching passages, and saves your draft with its citations.

活動後的留言想整理？影片裡的一段話想引用？讓你慣用的 AI 助理幫忙判讀與撰寫，MetaMuse 負責保存原文、搜尋段落，把草稿與引用一起留下。

A familiar task你可能也遇過

The event is over. The feedback is still scattered.

活動結束了，留言與影片還散在各處。

You want to know what people asked for, find a useful quote, and write a recap you can stand behind. Give your assistant permitted comments or local subtitles. MetaMuse keeps those sources available so you can check a draft against the original words.

想知道大家提了哪些需求、找出一段值得引用的話，再寫成一份能核對的回顧。把你有權使用的留言或本地字幕交給助理整理，MetaMuse 留下來源，讓你隨時回頭確認原文。

From input to a file you can keep從資料到一份可保存的文件

Bring the comments. Leave with a sourced draft.

帶入留言，帶走有來源的草稿。

You can use the terminal directly, or connect an AI assistant that can run MetaMuse tools.

你可以直接使用終端機，也可以接上能操作 MetaMuse 工具的 AI 助理。

01

Bring your files

匯入資料

Import permitted local comments, text or SRT/VTT subtitles into a project.

將有權使用的本地留言、文字或 SRT/VTT 字幕匯入專案。

02

Find the original

找到原文

Search for a word such as subtitles. Open the matching text and its source reference.

例如搜尋「字幕」，查看命中的原文與來源引用。

03

Write with your assistant

一起寫回顧

Your assistant groups requests and writes. Save the draft with the sources you reviewed.

由你的 AI 助理分組、判讀與撰寫，再連同你核對過的引用保存草稿。

04

Read and keep it

閱讀並留下

Preview the draft and export Markdown or another local format. Check the wording against the cited material.

預覽草稿，匯出 Markdown 等本地格式，對照引用確認文字是否忠實。

When it helps適合拿來做什麼

Less hunting for the original. More time for the recap.

少一點翻找原文，多一點時間整理重點。

Start with local files. Add an assistant when you want help interpreting and writing.

先從本地檔案開始，需要判讀與撰寫時，再交給你的 AI 助理協助。

01

Review event feedback

整理活動回饋

Find comments about the next event, accessibility requests or missing materials. Your assistant can turn the selected evidence into a recap.

找出對下一場活動的建議、無障礙需求或索取講義的留言，再讓助理依選好的原文寫回顧。

02

Find a transcript passage

找回字幕段落

Import local SRT or VTT files and search for the words you want to quote.

匯入本地 SRT 或 VTT 字幕，用關鍵字找出想引用的段落。

03

Check where a claim came from

核對一句話的來源

Keep source references and exact text revisions alongside a draft, so you can compare the wording with the original.

將來源引用與原文版本連同草稿保存，需要時可以對照文字。

04

Use your usual AI assistant

接上慣用的 AI 助理

Connect through CLI or MCP. The assistant asks questions and writes; MetaMuse handles the local records.

透過 CLI 或 MCP 連接。助理負責提問與撰寫，MetaMuse 負責保存本地資料。

05

Ask Muse a follow-up

選擇向 Muse 追問

Muse is optional and needs separate setup and human approval. Real-account use is still awaiting LIVE verification.

Muse 是可選的協作者，需要另外設定及人類授權。真實帳號使用仍待 LIVE 驗證。

06

Keep a file you can use

留下能接著使用的文件

Export Markdown, text, CSV, JSONL or a bundle for your own review and editing. Publishing is not implemented.

匯出 Markdown、文字、CSV、JSONL 或資料套件，方便後續閱讀與編輯。目前尚未提供發布功能。

Before you start開始之前

A few practical questions.

幾個你可能想問的問題。

The first example uses local synthetic files, so you can see the result before connecting accounts or an assistant.

第一個範例只用本地合成檔案，先看到結果，再決定是否連接帳號或 AI 助理。

01

Do I need a Muse account?

一定要有 Muse 帳號嗎？

No account is needed for local import, search, drafts or exports. Muse is a separately configured, optional discussion partner.

本地匯入、搜尋、草稿與匯出不需要帳號。Muse 是需要另外設定的選用討論對象。

02

Will the example write with AI?

範例會直接用 AI 寫回顧嗎？

It saves a clearly labelled prewritten recap. For your own work, connect an AI assistant or provide the text yourself.

範例保存的是清楚標記的預寫回顧。處理自己的資料時，可以連接 AI 助理，或自行提供文字。

03

Can I paste a Facebook or video URL?

可以直接貼 Facebook 或影片網址嗎？

Remote collectors need their own setup and operator approval. They currently have synthetic tests, with real-account LIVE validation pending. Start with local files.

遠端收集需要各自的設定與操作者授權。目前已有合成資料測試，真實帳號 LIVE 驗證仍待完成。建議先從本地檔案開始。

04

Is this a web app?

這是網頁版工具嗎？

This page introduces a tool that runs on your computer through a terminal or a connected AI assistant. The source preview can be installed today; a packaged release is not published yet.

這裡是介紹頁。工具在你的電腦上，透過終端機或已連接的 AI 助理操作。目前可從原始碼安裝預覽版，尚未發布套件。

Open your first sourced recap.

打開你的第一份有來源回顧。

You need Git and uv. Install from source; uv manages Python 3.12. Installation downloads dependencies. The example then uses only local synthetic data and a prewritten recap, with no account or AI service.

需要先安裝 Git 與 uv。目前從原始碼安裝，由 uv 管理 Python 3.12。安裝時會下載依賴；之後的範例只用本地合成資料與預寫回顧，不需要帳號或 AI 服務。

本地匯入、搜尋、草稿與匯出已有離線測試。Muse 與遠端收集有合成資料測試，真實帳號 LIVE 驗證仍待完成。目前是原始碼預覽版，尚未發布套件。以下細節與 README 保持一致。

Implemented · offline tests

已實作 · 離線測試

  • Local import
    implemented with offline tests
    Local files and text. The local import path rejects URLs before a job exists; approved remote inputs use their own collector.
  • 本地匯入
    implemented with offline tests
    本地檔案與文字。本地匯入路徑會在建立工作前拒絕 URL；已核准的遠端輸入使用各自的收集流程。
  • Local media and subtitles
    implemented with offline tests
    Optional ffprobe; tests requiring it skip when absent.
  • 本地影音與字幕
    implemented with offline tests
    ffprobe 為選用；缺少執行檔時，相關測試會跳過。
  • Search
    implemented with offline tests
    Project-scoped search over imported evidence.
  • 搜尋
    implemented with offline tests
    在專案範圍內搜尋匯入的證據。
  • Packets
    implemented with offline tests
    Selection file to an exact pre-share preview.
  • 資料包
    implemented with offline tests
    由選取檔產生精確的分享前預覽。
  • Drafts
    implemented with offline tests
    Host-supplied text; no generation call.
  • 草稿
    implemented with offline tests
    主代理提供文字；不呼叫生成模型。
  • Exports
    implemented with offline tests
    Five local formats; no publish or upload.
  • 匯出
    implemented with offline tests
    五種本地格式；不發布、不上傳。
  • Muse lifecycle with the fixture backend
    implemented with offline tests
    Open, send, read and close offline; derived records retain backend=fixture, mock=true, research_complete=false.
  • fixture 後端的 Muse 流程
    implemented with offline tests
    離線開啟、送出、讀取與結束；衍生紀錄保留 backend=fixture、mock=true、research_complete=false。
  • Muse standard-VM transport
    implemented with offline tests
    Strict Noise key/nonce verification, durable trust and bounded wake/redial. AT-038 and AT-043 LIVE have not run; CVM is unsupported.
  • Muse 標準 VM 傳輸
    implemented with offline tests
    嚴格驗證 Noise 金鑰與 nonce、持久化信任紀錄，並有界喚醒與重連。AT-038、AT-043 尚未執行 LIVE；不支援 CVM。
  • MCP stdio
    implemented with offline tests
    Fifteen tools; stdout is protocol, logs go to stderr.
  • MCP stdio
    implemented with offline tests
    15 個工具；stdout 僅傳協定，日誌送至 stderr。
  • MCP attached worker
    implemented with offline tests
    metamuse mcp starts one worker; --no-worker opts out. One workspace executor holds the OS lock.
  • MCP 附掛 worker
    implemented with offline tests
    metamuse mcp 啟動一個 worker；--no-worker 可停用。同一工作區只有一個執行者持有 OS 鎖。
  • Approval previews and metamuse permit approve
    implemented with offline tests
    Human approval of the exact action; no MCP approval tool.
  • 核准預覽與 metamuse permit approve
    implemented with offline tests
    人類核准精確操作；MCP 沒有核准工具。
  • Remote media (B12)
    implemented with offline tests
    Exact-action approval preview and human permit approve. OFFLINE and FIXTURE evidence; AT-040 LIVE has not been run.
  • 遠端影音（B12）
    implemented with offline tests
    精確操作的核准預覽與人類執行的 permit approve。已有 OFFLINE 與 FIXTURE 證據；尚未執行 AT-040 LIVE。
  • Facebook posts (B13)
    implemented with offline tests
    One operator-approved post per job, rendered in sandboxed Chromium through a policy-checked local proxy. Tested only on synthetic loopback pages; requires the facebook extra and Playwright Chromium. Human approval uses metamuse permit create; Facebook approval preview is not wired yet. No real-account run.
  • Facebook 貼文（B13）
    implemented with offline tests
    每個工作限一則操作者核准的貼文，以沙盒 Chromium 經過本地政策檢查代理呈現。僅以合成的本機回環頁面測試；需要 facebook 選用依賴與 Playwright Chromium。由人類執行 metamuse permit create 核准；Facebook 核准預覽流程尚未接上。未曾使用真實帳號執行。
  • CI
    implemented with offline tests
    GitHub Actions check runs the offline gates, sandboxed loopback Chromium browser tests (browser skips fail CI), and wheel smoke on every PR and main push; required status check on main since 2026-10-14.
  • CI
    implemented with offline tests
    GitHub Actions check 在每個 PR 與 main push 執行離線檢查、沙盒 Chromium 本機回環瀏覽器測試（跳過瀏覽器測試即失敗）及 wheel smoke；自 2026-10-14 起為 main 的必要狀態檢查。
